# 仕組み

## 登場する 3 者

```
 ┌────────────────────┐   API キー（igk_）   ┌──────────────────┐
 │ 自社バックエンド     │ ───────────────────▶ │ Intentgate API    │
 │ （元請・アプリ運営） │ ◀─────────────────── │                  │
 └────────────────────┘                      └──────────────────┘
        ▲  自社のログインで認証                     ▲  端末トークン（igd_）
        │                                          │  打刻の申請と完了
 ┌────────────────────────────────────────────────────┐
 │ 作業員アプリ（作業員のスマホ。位置情報とパスキー）           │
 └────────────────────────────────────────────────────┘
```

- **自社バックエンド**は API キーを持ちます。作業員の登録、パスキー登録の中継、端末の発行、現場（位置と半径）の管理、利用量の取得を行います。**API キーをアプリに埋め込まないでください。**
- **作業員アプリ**は端末トークンだけを持ち、打刻のときに Intentgate と直接やり取りします。電波がつながっていることが前提です。
- **Intentgate API** は打刻ごとにイベントを確定してチャレンジを発行し、パスキーの署名を検証して記録し、課金単位を数えます。

現場に QR やタブレットは置きません。

## 打刻の流れ

1. 作業員アプリが位置を測ります（緯度、経度、精度）。
2. アプリが `POST /v1/devices/{id}/checkins` で「種別・現場・位置」を送ります。
3. サーバーがイベントを確定します。時刻はサーバーの時計、nonce はサーバーの乱数、打刻 ID もサーバーが付けます。応答にはイベントとチャレンジ（イベントのハッシュ）が入っています。
4. SDK が、イベントが申請どおりか、チャレンジがイベントのハッシュと一致するかを確かめます。違えば署名しません。
5. 作業員が生体認証でパスキーに署名させます（UV 必須）。
6. アプリが `POST /v1/devices/{id}/checkins/{checkin_id}/complete` で署名を送ります。サーバーが検証して記録し、`accepted` と位置の判定（フラグ、現場からの距離）を返します。

チャレンジの有効期限は 180 秒です。通信が切れて完了の応答が届かなかったときは、同じ署名をもう一度送ってください。二重には記録されず、`duplicate` と記録済みの結果が返ります。

## 何が証明できるか

| 証明できること | 根拠 |
| --- | --- |
| 登録済みの作業員本人が、その端末で、生体認証をして承認した | パスキーの署名（UV 必須）。パスキーは作業員ごとに登録 |
| 承認した内容（種別・現場・位置・時刻）が書き換えられていない | チャレンジがイベント全体のハッシュで、それに署名している |
| 打刻の時刻 | サーバーの時刻。スマホの時計を変えても影響しない |
| 同じ打刻を二重に数えない | 打刻ごとのサーバー nonce と、1 回限りの完了 |

記録は「イベント＋パスキーの署名」の組で保存します。パスキーの公開鍵があれば、誰でも後から検証できます（管理 API の `GET /v1/events/{checkin_id}`）。

## 証明できないこと

正直に伝えるべき限界です。

- **位置情報の偽装**: root 化した端末や位置偽装アプリを使えば、スマホが報告する位置はごまかせます。Intentgate はスマホが報告した位置を記録し、現場からの距離で判定します。割り当てや勤務記録との突き合わせ、「要確認」の確認で補ってください。
- **乗っ取られた端末**: 端末そのものが乗っ取られていれば、表示を偽って署名させることはできます。生体認証は「本人が承認した」ことを示しますが、端末の健全性までは示しません。
- **なりすまし登録**: 最初のパスキー登録で本人確認をするのは自社バックエンドの責任です。登録時の本人確認（社員番号と対面確認など）を必ず行ってください。

## フラグ（要確認）

署名は正しいものの確認が必要な打刻には、**拒否せずにフラグを付けて記録します**。GPS の誤差で正しい打刻を落とさないためです。管理画面では「要確認」として表示されます。

| フラグ | 意味 |
| --- | --- |
| `outside_site` | 現場の中心からの距離が「半径＋位置の精度」を超えている（現場外） |
| `low_accuracy` | 位置の精度が 100 m より悪い |
| `unassigned_site` | その日に割り当てのない現場で打刻した |

完了の応答の `flags` と `distance_m` をアプリに表示すれば、作業員がその場で気付けます。

## 現場の位置

現場は中心の緯度・経度と半径（10〜5,000 m）を持ちます。現場を作るときに必須で、後から変更できます（管理画面の現場の詳細、または `PATCH /v1/sites/{id}`）。位置が未設定の現場では打刻できません（`site_location_missing`）。

## 課金単位

**作業員 × 現場 × 日**です。日付はサーバーの時刻を現場のタイムゾーンで数えます。同じ日に同じ現場で何回打刻しても 1 単位です。課金は打刻された現場を持つテナントに付きます。フラグ付きの打刻も数えます。テストモードは課金されません。
