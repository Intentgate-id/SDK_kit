# 仕組み

## 登場する 4 者

```
 ┌────────────────────┐   API キー（igk_）   ┌──────────────────┐
 │ 自社バックエンド     │ ───────────────────▶ │ Intentgate API    │
 │ （元請・アプリ運営） │ ◀─────────────────── │                  │
 └────────────────────┘                      └──────────────────┘
        ▲  自社のログインで認証                     ▲  端末トークン（igd_）
        │                                          │  nonce の受け取りと打刻のアップロード
 ┌────────────────────┐   QR を読む   ┌──────────────────┐
 │ 作業員アプリ         │ ◀──────────── │ 現場タブレット      │
 │ （作業員のスマホ）   │              │ （30 秒ごとの署名 QR）│
 └────────────────────┘              └──────────────────┘
```

- **自社バックエンド**は API キーを持ちます。作業員の登録、パスキー登録の中継、端末の発行、現場の管理、利用量の取得を行います。**API キーをアプリに埋め込まないでください。**
- **作業員アプリ**は端末トークンだけを持ちます。オンラインのときに nonce の束を受け取り、オフラインで打刻し、つながったときにまとめて送ります。
- **現場タブレット**は現場ごとの Ed25519 秘密鍵で QR を署名します。ネットワークは要りません。
- **Intentgate API** は署名を検証して打刻を確定し、課金単位を数えます。

## 打刻の流れ

1. 作業員アプリが現場タブレットの QR を読みます。
2. SDK が「種別・現場トークン・端末・連番・端末の時刻」から WebAuthn のチャレンジを作ります。
3. 作業員が生体認証でパスキーに署名させます（ここまでオフラインで完結します）。
4. 電波が戻ったら、SDK がたまった記録をアップロードします。サーバーは 1 件ずつ検証し、`accepted` / `duplicate` / `rejected` を返します。

## 何が証明できるか

| 証明できること | 根拠 |
| --- | --- |
| 登録済みの作業員本人が、その端末で、生体認証をして承認した | パスキーの署名（UV 必須）。パスキーは作業員ごとに登録 |
| その現場のその時間帯の QR を読んだ | 現場タブレットの Ed25519 署名と 30 秒の時間窓 |
| 打刻の内容（種別・現場・時刻）が書き換えられていない | チャレンジが内容のハッシュを含み、それに署名している |
| 同じ打刻を二重に数えない | 端末ごとの連番と、サーバーが導出する一回限りの nonce |

## 証明できないこと

正直に伝えるべき限界です。

- **QR の転送**: QR の写真を現場の外に送れば、30 秒以内なら離れた場所から読めます。時間窓が短いので難しくはなりますが、不可能ではありません。位置情報などを `attributes` に入れて補えます（Intentgate は値を検証しません）。
- **端末の時計**: 端末の時刻はずらせます。サーバーは QR の時刻（タブレットの時計）で日付を決め、端末時刻との差が 5 分を超えると `clock_skew` のフラグを付けます。
- **乗っ取られた端末**: 端末そのものが乗っ取られていれば、表示を偽って署名させることはできます。生体認証は「本人が承認した」ことを示しますが、端末の健全性までは示しません。
- **なりすまし登録**: 最初のパスキー登録で本人確認をするのは自社バックエンドの責任です。登録時の本人確認（社員番号と対面確認など）を必ず行ってください。

## フラグ

検証には通ったが確認が必要な打刻には、拒否せずにフラグを付けます。

| フラグ | 意味 |
| --- | --- |
| `clock_skew` | 端末の時刻と QR の時刻が 5 分以上ずれている |
| `unassigned_site` | その日に割り当てのない現場で打刻した |

## 課金単位

**作業員 × 現場 × 日**です。日付は QR の時刻を現場のタイムゾーンで数えます。同じ日に同じ現場で何回打刻しても 1 単位です。課金は打刻された現場を持つテナントに付きます。テストモードは課金されません。

## オフラインの期限

nonce の束には `lock_after`（既定で受け取りから 7 日）があります。これを過ぎると、同期するまで SDK は打刻を止めます。束は既定で 50 回分です。
